# 微信云托管部署手册

> 目标：一个 Docker 镜像同时提供管理后台（Vue3）与 Spring Boot API（含小程序接口）。
>
> 架构：容器内 nginx（80）托管前端静态文件 + 反向代理；Spring Boot（48080）提供 API。
> 数据库使用微信云托管 MySQL，Redis 使用腾讯云 Redis（需打通 VPC），文件使用腾讯云 COS。

---

## 0. 前置准备

| 项 | 要求 |
|---|---|
| 构建机 | 能运行 Docker；AMD64（Apple Silicon 本机用 `--platform linux/amd64`） |
| 后端 | JDK 25 + Maven 3.9+ |
| 前端 | Node.js >= 20.19 + pnpm >= 10 |
| 腾讯云 | 已开通微信云托管、容器镜像服务（TCR/CCR）、Redis、COS |
| 微信 | 小程序 AppID / Secret；支付商户号（如需支付） |

> 注意：`yudao-ui/yudao-ui-admin-vue3/.env.prod` 中 `VITE_BASE_URL` 必须为空（同源部署），
> 该值是**打包期变量**，换域名必须重新构建前端。

## 1. 构建并推送镜像

### 1.1 一键构建（推荐）

```bash
# 镜像仓库地址以腾讯云控制台为准（CCR 个人版 / TCR 企业版）
bash deploy/build.sh ccr.ccs.tencentyun.com/<命名空间>/maritime-app 20261109
```

脚本依次执行：

1. `pnpm build:prod` → `yudao-ui/yudao-ui-admin-vue3/dist-prod/`
2. `mvn -T 4 -Dmaven.test.skip=true clean package -pl yudao-server -am` → `yudao-server/target/yudao-server.jar`
3. `deploy/prepare-runtime.sh` → 装配 `deploy/runtime/{app.jar,web/}`
4. 校验 jar 中包含 maritime 模块、前端 index.html 存在，然后 `docker build --platform linux/amd64` → 运行时镜像

常用参数：

```bash
# 构建并推送（需先 docker login）
PUSH=1 bash deploy/build.sh ccr.ccs.tencentyun.com/<命名空间>/maritime-app 20261109

# 只改后端：跳过前端构建，复用上次的 dist-prod
SKIP_WEB=1 bash deploy/build.sh ...

# 只改前端：跳过后端构建，复用上次的 jar
SKIP_SERVER=1 bash deploy/build.sh ...
```

### 1.2 推送

```bash
docker login ccr.ccs.tencentyun.com
docker push ccr.ccs.tencentyun.com/<命名空间>/maritime-app:20261109
```

> Apple Silicon 必须使用 `--platform linux/amd64`，腾讯云运行的是 x86_64。
> 不要在本机用 Docker 跑完整的 Maven/pnpm 构建（模拟层很慢），先本机原生构建再装配镜像。

### 1.3 云上源码构建（可选）

也可以把仓库交给微信云托管构建，Dockerfile 路径填根目录 `Dockerfile`，端口填 `80`。
首次构建需要下载 Maven / pnpm 依赖，通常 15~30 分钟；务必保留根目录 `.dockerignore`。

> 云端构建慢的主要原因：每次都要重新拉基础镜像、下载全部 Maven/pnpm 依赖、编译整个多模块工程，
> 且构建器通常不保留 Docker 层缓存。Dockerfile 已为 npm、pnpm store、Maven `.m2` 增加
> BuildKit cache mount；若构建日志报 `unknown flag: --mount`，说明构建器不支持 BuildKit，
> 删掉对应 `--mount` 参数即可。
>
> 仓库中 `deploy/sql/` 的数据库导出文件（约 280MB）已被 `.dockerignore` 排除，
> 不要再提交新的导出文件；日常发版建议直接用 1.1 的本地镜像构建。

> 注意：云端源码构建要求 `yudao-ui/yudao-ui-admin-vue3` 已提交到 Git。
> 如果前端目录还在本地未提交，请使用镜像部署。

## 2. 创建云托管服务

1. 微信云托管控制台 → 选择环境 → 新建服务
2. 部署方式选择「镜像部署」，选择第 1 步推送的镜像；**不要选「官方模板」**
3. **端口填 `80`**（镜像内 nginx 监听 80；Spring Boot 的 48080 只在容器内供 nginx 反代，不能填 48080）
4. 实例规格建议 **2C4G 起**；最小实例数设为 `1`（避免冷启动影响定时任务和 WebSocket）
5. 如有「健康检查」配置，路径填 `/actuator/health`
6. 部署完成后记录平台生成的 HTTPS 域名（默认域名不需要 ICP 备案）

> ⚠️ 发布后检查「线上版本」卡片的「发布方式」：应为「镜像」或「Git 仓库」。
> 如果显示「官方模板 基于模板开发」，说明发布的是腾讯示例应用（首页是“欢迎使用微信云托管”），
> 不是你的代码，需要重新按「镜像」或「Git 仓库」发布。
>
> 如果端口误填 48080，健康检查能通过、接口也能用，但 `/` 会返回 Spring 的 404 JSON，
> 管理后台页面打不开——这是最容易误判为“部署成功但后台访问不了”的情况。

## 3. 环境变量

在「服务设置 → 环境变量」中添加：

| 变量 | 必填 | 示例 | 说明 |
|---|---|---|---|
| `SPRING_PROFILES_ACTIVE` | 是 | `prod` | 启用 `application-prod.yaml` |
| `MYSQL_ADDRESS` | 是 | `10.0.0.12:3306` | 云托管 MySQL 内网地址（绑定后可能自动注入） |
| `MYSQL_DATABASE` | 是 | `ruoyi-vue-pro` | 库名，需提前创建 |
| `MYSQL_USERNAME` | 是 | `yudao` | 数据库账号 |
| `MYSQL_PASSWORD` | 是 | `******` | 数据库密码 |
| `REDIS_HOST` | 是 | `10.0.1.20` | 腾讯云 Redis **内网地址** |
| `REDIS_PORT` | 是 | `6379` | |
| `REDIS_PASSWORD` | 否 | `******` | Redis 有密码时填写 |
| `REDIS_DATABASE` | 否 | `0` | |
| `WX_MINIAPP_APPID` | 是 | `wx...` | 小程序 AppID |
| `WX_MINIAPP_SECRET` | 是 | `...` | 小程序 Secret |
| `WX_MP_APP_ID` | 否 | `wx...` | 公众号 AppID（不用可留空） |
| `WX_MP_SECRET` | 否 | `...` | 公众号 Secret |
| `ADMIN_UI_URL` | 否 | `https://xxx.sh.run.tcloudbase.com` | 后台地址（Swagger 展示用） |
| `PAY_ORDER_NOTIFY_URL` | 支付时必填 | `https://xxx.../admin-api/pay/notify/order` | 微信支付回调 |
| `PAY_REFUND_NOTIFY_URL` | 支付时必填 | `https://xxx.../admin-api/pay/notify/refund` | 退款回调 |
| `PAY_TRANSFER_NOTIFY_URL` | 支付时必填 | `https://xxx.../admin-api/pay/notify/transfer` | 转账回调 |
| `JAVA_OPTS` | 否 | `-XX:MaxRAMPercentage=75 ...` | 覆盖镜像默认 JVM 参数 |

> JVM 默认参数已包含 JDK 25 必需的
> `--enable-native-access=ALL-UNNAMED --sun-misc-unsafe-memory-access=allow`，一般无需覆盖。

## 4. 打通 Redis VPC

微信云托管访问腾讯云 Redis 需要通过私有网络：

1. 确认 Redis 实例与云托管环境在**同一地域**
2. 云托管控制台 → 服务设置 → 网络 → 开启 **VPC / 私有网络** 访问
3. 选择与 Redis 相同的 VPC 和子网
4. 在 Redis 实例的**安全组 / 白名单**中放行该子网网段
5. 环境变量使用 Redis 的**内网地址**，不要用公网地址

验证：部署后在容器日志中确认没有 Redis 连接超时；登录后台能正常写入缓存即通。

## 5. 初始化数据库

### 5.1 创建数据库

在云托管 MySQL 控制台创建库（例如 `ruoyi-vue-pro`，字符集 `utf8mb4`），并为账号授权。

### 5.2 导入 SQL（推荐直接迁移本地库）

> ⚠️ 不要无脑把 `script/docker/sql/mysql/` 下 01~28 全部按顺序导入。
> 其中 `08-maritime-init.sql` 已经是最新的完整 maritime 表结构（包含 `active_flag`、
> `degrade_reason`、`latitude/longitude`、`extra_fee_items` 等后续字段），
> 再执行 `17-maritime-state-machine.sql` 会因列重复而失败。

**方案 A（推荐）：把当前本地开发库整体迁移到云数据库**

```bash
# 1) 本地导出（--single-transaction 不锁表）
mysqldump -h127.0.0.1 -uroot -p \
  --single-transaction --routines --triggers \
  --default-character-set=utf8mb4 --set-gtid-purged=OFF \
  ruoyi-vue-pro > ruoyi-vue-pro-prod.sql

# 2) 导入云 MySQL（建议通过 DMS 或 VPC 内跳板机执行）
mysql -h<云 MySQL 地址> -u<账号> -p ruoyi-vue-pro < ruoyi-vue-pro-prod.sql
```

优点：schema、菜单、字典、业务数据、管理员密码与当前开发环境完全一致，不会有脚本版本漂移。

**方案 B：全新空库手工初始化**

按以下顺序导入（`06-ai.sql`、`07-mall.sql` 不使用对应模块时跳过）：

```
01-quartz.sql
02-ruoyi-vue-pro.sql
03-member.sql
04-pay.sql
05-mp.sql
08-maritime-init.sql          # 已包含最新完整 maritime 表结构
09-maritime-course-seed.sql   # 课程种子数据（可选）
10-maritime-demo-data.sql     # 演示数据（生产建议跳过）
10-maritime-fee-template.sql
11-maritime-remove-fee-config-page.sql
12-maritime-venue-coordinates.sql
13-maritime-school-library.sql
14-maritime-address-structure.sql
15-maritime-extra-fee.sql
16-maritime-session-code-auto.sql
# 17 跳过：degrade_reason / manual_task 已包含在 08 中，重复执行会报列已存在
18-maritime-notify.sql
19-remove-referral.sql
20-maritime-remove-home-config-merge-refund.sql
21-maritime-rename-enrollment-menus.sql
22-maritime-remove-user-message.sql
23-maritime-finance-menu.sql
24-remove-mall-ai-iot-menus.sql
25-remove-crm-mes-menus.sql
```

说明：

- 12/14/15/16/18/19 等增量脚本内部有 `information_schema` 判断，字段已存在时会自动跳过
- 云控制台的 SQL 编辑器可能限制单次文件大小，大文件建议用客户端 / DMS 导入
- 导入完成后，后台默认管理员为 `admin / admin123`，**上线前必须修改密码**

## 6. 配置文件存储（COS）

容器文件系统是临时的，绝不能使用「本地存储」。部署后：

1. 后台 → 基础设施 → 文件配置 → 新增「腾讯云 COS」（S3 协议）
2. 填写 `endpoint`、`bucket`、`accessKey`、`accessSecret`
3. `domain` 填 COS 的 **HTTPS 公网域名**
4. 保存后设为**主配置**

> 小程序、后台的图片/附件都依赖这个域名；域名必须是 HTTPS，否则微信会拦截。

---

## 7. 域名与小程序配置

1. 云托管默认域名已是 HTTPS，**无需 ICP 备案**
2. 微信公众平台 → 开发管理 → 服务器域名，添加：
   - request 合法域名：`https://<云托管域名>`
   - uploadFile / downloadFile 合法域名：`https://<云托管域名>`（如上传走后台）
   如果文件走 COS，还需要把 COS 域名加入 downloadFile 合法域名
3. 小程序 `yudao-ui/yudao-mall-uniapp/.env`：

```dotenv
SHOPRO_BASE_URL=https://<云托管域名>
SHOPRO_TRIAL_BASE_URL=https://<云托管域名>
SHOPRO_H5_URL=https://<H5 域名>
SHOPRO_STATIC_URL=https://<静态资源域名>
```

修改后重新编译发布小程序。

4. 后台「系统管理 → 社交平台 → 社交客户端」中确认微信小程序 AppID / Secret 与环境变量一致。
5. 如果修改了多租户名称，同步修改前端 `.env` 的 `VITE_APP_DEFAULT_LOGIN_TENANT` 并重新构建前端。

---

## 8. 微信支付

1. 后台配置微信支付渠道（商户号、API v3 密钥、证书）
2. 确认支付回调地址使用云托管默认域名：
   - `https://<域名>/admin-api/pay/notify/order`
   - `https://<域名>/admin-api/pay/notify/refund`
   - `https://<域名>/admin-api/pay/notify/transfer`
3. 在微信支付商户平台确认回调域名可达（云托管默认域名公网可直接访问）
4. 首次上线建议用 0.01 元做真实支付 + 退款验证

## 9. 发版与回滚

```bash
# 构建并推送新版本
PUSH=1 bash deploy/build.sh <镜像仓库> 20261201

# 云托管控制台 → 服务 → 新建版本 → 选择新镜像 → 灰度/全量发布
```

- 每次发版保留上一个镜像 tag，出问题直接在「版本管理」回滚
- 前端是打包期配置，**改 `.env.prod` 后必须重新构建镜像**，只改云托管环境变量无效
- 数据库变更脚本单独执行，执行前先备份

## 10. 常见问题

| 现象 | 排查 |
|---|---|
| 访问首页是「欢迎使用微信云托管」示例页 | 线上版本的「发布方式」是「官方模板」；重新按「镜像」或「Git 仓库」发布 |
| 接口正常但后台页面打不开（`/` 返回 Spring 404 JSON） | 服务端口填成了 48080；改成 **80**（容器内 nginx），Spring 48080 仅供反代 |
| 页面能打开，接口 502 | 看容器日志 Java 是否启动失败；检查 `SPRING_PROFILES_ACTIVE=prod`、数据库/Redis 环境变量 |
| 登录报「验证码不能为空」 | 前端构建时 `.env.prod` 的 `VITE_APP_CAPTCHA_ENABLE` 必须为 `true`（已写入） |
| 登录后接口 401 | 检查 Redis 是否连通；Token 存在 Redis |
| 上传成功但图片打不开 | 检查 `infra_file_config` 主配置的 `domain` 是否为 HTTPS 公网域名 |
| 小程序请求失败 | 检查 request 合法域名是否加入；`SHOPRO_BASE_URL` 是否为 HTTPS |
| WebSocket 连不上 | 云托管需支持 WebSocket；nginx 已配置 `/infra/ws` 升级；多实例时把 `yudao.websocket.sender-type` 改为 `redis` |
| 启动时区/时间不对 | 镜像已设置 `TZ=Asia/Shanghai`；数据库连接串已带 `serverTimezone=Asia/Shanghai` |
| 镜像启动即退出 | 看日志；常见为 Redis/MySQL 连不上导致 Spring 启动失败，或健康检查路径配置错误 |
| 数据/图片重启后丢失 | 文件存储未切到 COS；容器本地磁盘不可持久化 |
